## 3. 数据与合规门槛（15 min）

### 3.1 数据现状（评审基线）

| 数据资产 | 当前量 | Phase 4 建议目标 |
|---|---:|---:|
| 事故案例 `accident_case_library` | 20（种子） | ≥50（L2）/ ≥200（L3） |
| 强规则 YAML | 10 条 | 维持，回测引用 |
| 指标目录 | 32 条 | 维持，权重校准引用 |
| 演示项目 | 2（P001/P002） | 压测合成数据，不改生产 |

### 3.2 合规红线（延续 `AGENTS.md`，Phase 4 不放宽）

| 项 | 规则 |
|---|---|
| behavior_memory | 不得存身份证、体检明细、人脸原图、原始视频；需合规评审纪要 |
| 贝叶斯 / 回测输出 | 不得作为处罚、清退、停工的**唯一**依据；须 `need_human_review` |
| 压测 | 仅用合成/脱敏数据，禁止把生产库拉入压测环境 |
| 权重变更 | 须版本号 + `effective_time` + 可回滚（对齐技术文档 config_scope） |

**决策：** behavior_memory 无合规签字 → **4-E 整包冻结**。

## 4. 环境与成本（10 min）

| 组件 | Phase 3 现状 | Phase 4 变更 |
|---|---|---|
| MySQL | 宿主机/compose | 压测需独立 schema 或合成灌数脚本 |
| Redis / Milvus / Neo4j | 已验收 | 无强制新增；RAG/图谱随压测只读验证 |
| 视频 AI / BIM | 无 | 需边缘网关或 BIM 模型源，**默认不新增 compose 服务** |
| 算力 | 本地开发机 | 压测可用 `--scale` 合成；2000 项目建议 CI/专项机 |

**决策：** 开发机内存仍建议 ≥16GB；2000 项目压测可放夜间 CI，不阻塞日常 vibe coding。

## 5. 排期与首 Sprint（15 min）

**推荐 8 周排期（可调）：**

| 周 | Sprint | 交付 |

| W1–W2 | 4-A | 项目类型权重矩阵 + DF 因子表 + 画像重算回归测试 |
