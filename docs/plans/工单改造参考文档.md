**Goal:** 在项目维度实现「总承包安全员上传隐患（图片+文字）→ 安全总监审批派发 → 分包安全员整改回复 → 总承包验收闭环」的完整后端链路，含岗位级 Mock 权限与业务数据联动（hazard ↔ work_order ↔ 画像重算）。

**Architecture:** 不修改现有 7 态状态机；新增 `project_user` 岗位表与 `domain/hazard_workflow.py` 角色×动作矩阵；隐患上传与工单流转分 service 层，`POST hazards` 单事务创建 hazard + work_order；附件 MVP 用本地文件存储 + JSON 元数据；`review_pass` 时同步关闭 hazard 并触发项目级画像重算。

**Tech Stack:** FastAPI、SQLAlchemy 2、Alembic、Pydantic v2、pytest；Mock 鉴权（Header）；本地 `uploads/` 目录存图（禁止把二进制写入 MySQL）。

## 1. 背景与现状

### 1.1 业务流程（目标）

```text
总承包安全员(gc_safety_officer)
  → POST 隐患(图片+描述+责任分包)
  → hazard(open) + work_order(pending_confirm)

安全总监(safety_director)
  → confirm（指定分包安全员、整改期限）
  → work_order(dispatched)

分包安全员(sub_safety_officer)
  → accept → processing
  → submit_result（整改说明+整改后图片）
  → waiting_review

总承包安全员
  → review_pass → closed + hazard(closed) + 画像重算
  → review_reject → processing（带 reject_reason）
```

### 1.2 代码基线（已实现）

| 模块 | 路径 | 状态 |
|---|---|---|
| 状态机 | `backend/app/domain/work_orders.py` | ✅ 7 态 + 6 条合法转换 |
| 工单 service | `backend/app/services/work_orders/service.py` | ✅ 列表/创建/流转/超期升级 |
| 工单 endpoint | `backend/app/api/v1/endpoints/work_orders.py` | ✅ 无角色校验 |
| 隐患表 | `backend/app/infrastructure/database/models.py::Hazard` | ✅ 无 API |
| 工单 attachments 字段 | `SafetyWorkOrder.attachments` JSON | ✅ 未使用 |
| Mock 用户 | `backend/app/core/security.py` | ✅ `MockUser` + `apply_data_scope` |
| 前端闭环 | `frontend/src/pages/WorkOrdersPage.vue` | ✅ 无角色/附件（本计划后端优先） |

### 1.3 缺口（本计划补齐）

1. 隐患上传固定范式（multipart：图片 + 文字描述）
2. 项目级岗位账号（`project_user`）与流转权限
3. 流转审计日志（`work_order_flow_log`）
4. 闭环联动（closed → hazard.closed → profile recalculate）

## 3. 数据模型

### 3.1 新增表 `project_user`

```sql
CREATE TABLE project_user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tenant_id VARCHAR(64) NOT NULL,
    company_id VARCHAR(64) NOT NULL,
    org_path VARCHAR(512) NOT NULL,
    project_id VARCHAR(64) NOT NULL,
    user_id VARCHAR(64) NOT NULL,
    user_name VARCHAR(128) NOT NULL,
    role_code VARCHAR(64) NOT NULL,
    subcontractor_id VARCHAR(64) NULL,
    status VARCHAR(32) NOT NULL DEFAULT 'active',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_project_user_role (project_id, user_id, role_code),
    KEY ix_project_user_project (project_id),
    KEY ix_project_user_sub (subcontractor_id)
);
```

**role_code 枚举（本 Task 固定 3 种）：**

| role_code | 中文 | subcontractor_id |
|---|---|---|
| `gc_safety_officer` | 总承包项目安全员 | NULL |
| `safety_director` | 项目安全总监 | NULL |
| `sub_safety_officer` | 分包安全员 | 必填 |

### 3.2 扩展 `hazard` 表

| 字段 | 类型 | 说明 |
|---|---|---|
| `discovered_by_user_id` | VARCHAR(64) | 发现人 |
| `location` | VARCHAR(255) NULL | 位置描述 |
| `attachments` | JSON NULL | 发现阶段附件元数据 |
| `work_order_id` | VARCHAR(64) NULL INDEX | 关联工单 1:1 |

### 3.3 新增表 `work_order_flow_log`

| 字段 | 类型 | 说明 |
|---|---|---|
| `work_order_id` | VARCHAR(64) | 工单 |
| `from_status` | VARCHAR(32) | 原状态 |
| `to_status` | VARCHAR(32) | 新状态 |
| `action` | VARCHAR(64) | confirm / accept / submit_result / … |
| `operator_user_id` | VARCHAR(64) | 操作人 |
| `operator_role` | VARCHAR(64) | 操作角色 |
| `comment` | TEXT NULL | 备注 |
| `reject_reason` | TEXT NULL | 驳回原因 |
| `attachments` | JSON NULL | 本次动作附件快照 |
| `created_at` | DATETIME | 时间 |

### 3.4 附件 JSON 范式（hazard + work_order 共用）

```json
{
  "items": [
    {
      "file_id": "F-20260605-ABC123",
      "phase": "discovery",
      "content_type": "image/jpeg",
      "file_name": "hazard-01.jpg",
      "url": "/api/v1/files/F-20260605-ABC123",
      "sha256": "hex-digest",
      "size_bytes": 102400,
      "uploaded_by": "U-GC-01",
      "uploaded_at": "2026-06-05T10:00:00+08:00"
    }
  ]
}
```

**phase 枚举：** `discovery` | `rectification` | `review`

**校验规则：**

- 上传：`discovery` ≥ 1 张，≤ 9 张；单张 ≤ 5MB；仅 `image/jpeg` / `image/png`
- `submit_result`：`rectification` ≥ 1 张
- DB 禁止存二进制，只存元数据 + 本地路径

## 4. 角色 × 动作权限矩阵

实现位置：`backend/app/domain/hazard_workflow.py`（纯函数，无 DB 依赖）

| 当前 status | action | 允许 role_code | 附加条件 |
|---|---|---|---|
| `pending_confirm` | `confirm` | `safety_director` | 同 project_id |
| `dispatched` | `accept` | `sub_safety_officer` | `user.subcontractor_id == order.subcontractor_id` |
| `processing` | `submit_result` | `sub_safety_officer` | 同上；必须带 rectification 附件 |
| `waiting_review` | `review_pass` | `gc_safety_officer` | 同 project_id |
| `waiting_review` | `review_reject` | `gc_safety_officer` | 必须 `reject_reason` |
| `processing` | `timeout` | `system` | 已有超期 API，角色校验跳过 |

**列表可见性（`list_work_orders` 增强）：**

- `gc_safety_officer` / `safety_director`：授权项目内全部工单
- `sub_safety_officer`：仅 `subcontractor_id` 匹配工单

**Mock Header 扩展（`get_current_user`）：**

| Header | 说明 |
|---|---|
| `X-Mock-User-Id` | 用户 ID |
| `X-Role` | 角色（与 project_user.role_code 对齐） |
| `X-Scope-Type` | `project` |
| `X-Authorized-Project-Ids` | 如 `P002` |
| `X-Subcontractor-Id` | 分包安全员必填，如 `S003` |

权限校验：`permissions.assert_project_membership(db, user, project_id, role_code)` 查 `project_user` 表，**不信任 Header 单独作为授权依据**。

## 5. API 契约

### 5.1 POST `/api/v1/projects/{project_id}/hazards`

**权限：** `gc_safety_officer` + 项目 scope

**Content-Type:** `multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|---|---|:---:|---|
| `description` | string | ✅ | ≥ 10 字 |
| `hazard_type` | string | ✅ | 如 `临边防护` |
| `hazard_level` | string | ✅ | `general` / `major` |
| `subcontractor_id` | string | ✅ | 责任分包 |
| `due_date` | date | ✅ | 整改期限 |
| `location` | string | 否 | 位置 |
| `images` | file[] | ✅ | 1–9 张 |

**响应 data：**

```json
{
  "hazard_id": "H-xxx",
  "work_order_id": "WO-xxx",
  "status": "open",
  "work_order_status": "pending_confirm"
}
```

**副作用（单事务）：**

1. 写 `hazard`（status=open）
2. 写 `safety_work_order`（status=pending_confirm, source_type=hazard, work_order_type=rectification）
3. 写首条 `work_order_flow_log`（action=create）

### 5.2 PATCH `/api/v1/work-orders/{work_order_id}/status`

**增强请求体 `WorkOrderStatusUpdate`：**

| 字段 | 适用 action | 说明 |
|---|---|---|
| `action` | 全部 | 必填 |
| `comment` | 全部 | 可选备注 |
| `assignee_user_id` | `confirm` | 分包安全员 user_id |
| `due_time` | `confirm` | 整改截止时间 |
| `reject_reason` | `review_reject` | 必填 |
| `attachments` | `submit_result` | 或由 multipart images 填充 |

**错误码：**

| HTTP | code/detail | 场景 |
|---:|---|---|
| 403 | 无权限 | 角色不匹配 |
| 404 | Work order not found | 不存在或 scope 外 |
| 409 | Invalid work-order transition | 状态机非法 |
| 422 | 缺少整改图片 / reject_reason | 业务校验 |

### 5.3 GET `/api/v1/work-orders/{work_order_id}`

返回工单详情 + `attachments` + `flow_logs[]` + 关联 `hazard_id`（via source_id）。

### 5.4 GET `/api/v1/files/{file_id}`

本地文件只读下载；校验 tenant + project scope。
