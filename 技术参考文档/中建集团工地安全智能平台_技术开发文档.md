## 1. 项目概述

### 1.1 项目背景

随着建筑行业安全管理要求的不断提高，传统的人工安全管理模式已难以满足大型工程项目的需求。中建集团作为行业领军企业，亟需构建一套智能化、数字化的安全管理平台，实现安全管理的精细化、智能化和可追溯化。

本项目旨在利用大语言模型（LLM）、智能问数引擎（NL2SQL）、四库协同存储架构等前沿技术，构建覆盖项目工地全场景的智能安全管理平台，提升安全管理效率，降低事故发生率。

### 1.2 项目目标

1. 实现安全报告（日报/周报/月报）的自然语言生成，减轻安监人员工作负担
2. 构建智能问答系统，支持安全知识查询和业务数据查询
3. 实现危险动火、危大工程等业务流程的智能审批
4. 建立工人反馈通道，实现投诉建议的闭环管理
5. 构建完整的用户画像体系，支持三级安全教育与体检管理
6. 实现监控视频的智能识别，自动检测安全帽、反光衣等

### 1.3 适用范围

本系统适用于中建集团下属各工程局、子公司及项目工地的安全管理工作，覆盖房建、市政、基础设施等各类工程项目。

## 3. 四库协同存储架构

### 3.1 架构设计原则

四库协同存储架构遵循"数据按特征分库"的原则，根据数据的结构特征、访问模式和使用场景，选择最适合的存储引擎，实现数据的高效存储和快速检索。

### 3.2 各库职责与数据模型

#### 3.2.1 MySQL - 结构化业务数据

MySQL存储所有结构化业务数据，包括隐患台账、人员档案、设备台账、检查记录、整改记录、培训记录等。采用主从复制架构保证高可用。

**核心数据表设计：**

```sql
-- 隐患台账表
CREATE TABLE hidden_danger (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    project_id VARCHAR(50) NOT NULL COMMENT '项目ID',
    zone VARCHAR(50) COMMENT '工区',
    location VARCHAR(200) COMMENT '具体位置',
    type VARCHAR(50) COMMENT '隐患类型',
    level ENUM('一般','重大') COMMENT '隐患等级',
    description TEXT COMMENT '隐患描述',
    discoverer_id VARCHAR(50) COMMENT '发现人ID',
    responsible_team VARCHAR(100) COMMENT '责任班组',
    status ENUM('待整改','整改中','已整改','已验收') COMMENT '状态',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_project_time (project_id, create_time),
    INDEX idx_type (type),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 3.2.2 Neo4j - 关系图谱

Neo4j存储项目-分包商-人员-隐患的关系图谱，支持复杂的关系查询和路径分析，用于风险传导分析、责任追溯等场景。

**图谱模型设计：**

```cypher
-- 节点类型
(:Project {id, name, type, start_date, end_date})
(:Subcontractor {id, name, qualification_level, safety_rating})
(:Team {id, name, work_type, leader_id})
(:Worker {id, name, work_type, entry_date, safety_score})
(:HiddenDanger {id, type, level, status, create_time})

-- 关系类型
(:Project)-[:HAS_SUBCONTRACTOR]->(:Subcontractor)
(:Subcontractor)-[:HAS_TEAM]->(:Team)
(:Team)-[:HAS_WORKER]->(:Worker)
(:Worker)-[:DISCOVERED]->(:HiddenDanger)
(:Worker)-[:RESPONSIBLE_FOR]->(:HiddenDanger)
(:HiddenDanger)-[:LOCATED_AT]->(:Project)
(:HiddenDanger)-[:SIMILAR_TO]->(:HiddenDanger)
```

#### 3.2.3 Milvus - 向量数据

Milvus存储百万级向量数据，包括安全知识库向量、工人行为embedding、事故案例向量等，支持高效的相似度检索。

**Collection设计：**

```json
{
    "collection_name": "safety_knowledge",
    "fields": [
        {"name": "id", "type": "INT64", "is_primary": true},
        {"name": "content", "type": "VARCHAR", "max_length": 2000},
        {"name": "embedding", "type": "FLOAT_VECTOR", "dim": 1024},
        {"name": "category", "type": "VARCHAR"},
        {"name": "source", "type": "VARCHAR"},
        {"name": "clause", "type": "VARCHAR"}
    ],
    "index": {
        "type": "IVF_FLAT",
        "metric_type": "COSINE",
        "params": {"nlist": 1024}
    }
}
```

#### 3.2.4 Redis - 多层缓存

Redis作为多层缓存层，缓存LLM会话上下文、NL2SQL查询结果、热点统计数据等，显著提升系统响应速度。

**缓存策略：**

| 缓存类型 | Key格式 | 过期时间 |
|----------|---------|----------|
| 会话缓存 | session:{user_id} | 30分钟 |
| NL2SQL结果 | nl2sql:{query_hash} | 5分钟 |
| 统计数据 | stats:{type}:{date} | 1小时 |
| 用户画像 | profile:{worker_id} | 24小时 |

## 4. Agent体系设计

### 4.1 Agent架构总览

系统采用多Agent协作架构，通过Agent Orchestrator进行统一调度和协调，各Agent专注于特定领域，通过消息传递实现协作。

### 4.2 核心Agent设计

#### 4.2.1 报告生成Agent

报告生成Agent负责将用户的自然语言指令转换为结构化的安全报告，支持日报、周报、月报及专项报告。

**处理流程：**

1. 意图解析：提取报告类型、时间范围、空间范围、关注主题
2. 数据聚合：通过NL2SQL查询MySQL，通过Cypher查询Neo4j
3. 内容生成：使用LLM整合数据，生成报告正文
4. 格式输出：生成Word/PDF/HTML格式的报告文件

#### 4.2.2 智能问答Agent

智能问答Agent支持两种问答模式：业务数据查询（NL2SQL）和安全知识问答（RAG）。

**NL2SQL流程：**

```
用户问题 → 意图分类 → Schema理解 → SQL生成 → SQL执行 → 结果解释 → 自然语言回答

示例：
问题: "三工区本月有多少高处作业隐患？"
SQL: SELECT COUNT(*) FROM hidden_danger 
     WHERE zone='三工区' 
     AND type='高处作业' 
     AND DATE_FORMAT(create_time,'%Y-%m')='2024-03'
答案: "三工区本月共发现高处作业隐患X起。"
```

#### 4.2.3 业务审批Agent

业务审批Agent负责危险动火作业、危大工程监督等业务流程的智能化审批，包括风险预评估、流程推进、结果通知等。

**危险动火审批流程：**

1. 申请人提交动火申请（地点、类型、时间、操作人）
2. AI风险预评估：动火等级识别、周边环境分析、人员资质核验
3. 生成风险评估报告和建议措施
4. 安全员审核 → 项目经理审批 → 安全总监备案
5. 审批结果通知 + 监督任务生成

#### 4.2.4 工人反馈Agent

工人反馈Agent处理工人的隐患举报、违规举报、投诉建议等反馈，实现从提交到闭环的全流程管理。

#### 4.2.5 监控识别Agent

监控识别Agent基于计算机视觉技术，实时分析监控视频，检测人员是否佩戴安全帽、穿着反光衣，以及是否完成人脸识别录入。

**识别功能清单：**

| 识别类型 | 功能描述 |
|----------|----------|
| 人脸识别 | 识别进入工地的人员，匹配人脸库判断是否已录入 |
| 安全帽检测 | 检测人员头部区域，判断是否佩戴安全帽 |
| 反光衣检测 | 检测人员躯干区域，判断是否穿着反光衣 |
| 陌生人告警 | 未录入人脸的人员进入工地时触发告警 |

## 5. 核心功能模块

### 5.1 报告生成模块

报告生成模块是系统的核心功能之一，旨在通过自然语言交互，自动生成各类安全管理报告，大幅提升安监人员的工作效率。

**支持的报告类型：**

| 报告类型 | 数据来源 | 核心指标 | 输出格式 |
|----------|----------|----------|----------|
| 日报 | 当日隐患、检查记录 | 今日发现数、整改数 | 简报(500字) |
| 周报 | 本周汇总、环比分析 | 周隐患趋势、分包商排名 | 标准报告(1500字) |
| 月报 | 月度统计、趋势分析 | 月度KPI、风险预警 | 正式报告(3000字+) |
| 专项报告 | 特定主题深挖 | 高处作业/用电安全专项 | 定制报告 |

### 5.2 用户画像模块

用户画像模块构建完整的工人安全画像体系，整合三级安全教育成绩、体检报告、安全行为等多维度数据，实现精准的安全风险评估。

**画像维度：**

- **基础信息**：工种、班组、分包商、入场时间
- **三级安全教育**：公司级、项目级、班组级教育成绩与时效
- **体检信息**：体检日期、有效期、结论、作业限制
- **安全行为**：隐患发现数、整改数、违规次数、培训参与率
- **综合评分**：基于多维度数据计算的安全评分与风险等级

**综合评分算法：**

```
综合安全评分 = 
    三级安全教育(20%) + 
    体检合规(15%) + 
    安全行为(35%) + 
    知识掌握(20%) + 
    班组影响(10%)

风险等级判定：
- 80-100分：低风险（绿色）
- 60-79分：中风险（黄色）
- 0-59分：高风险（红色）
```

### 5.3 安全知识库模块

安全知识库模块内置建筑项目安全知识手册，支持自然语言问答，为现场人员提供即时的安全知识查询服务。

**知识库内容：**

- **法规标准**：《建筑施工安全检查标准》(JGJ 59)、《危险性较大的分部分项工程安全管理规定》等
- **操作规程**：高处作业、临时用电、起重吊装等安全操作规程
- **事故案例**：历年典型事故案例分析、行业事故警示
- **培训教材**：三级安全教育教材、特种作业培训资料

## 6. 技术实现方案

### 6.1 NL2SQL实现方案

NL2SQL（自然语言转SQL）是智能问答Agent的核心能力，负责将用户的自然语言查询转换为可执行的SQL语句。

**技术方案：**

1. **基础模型**：采用开源的SQLCoder或CodeX作为基础模型
2. **微调训练**：收集历史SQL查询作为训练语料，进行领域微调
3. **Schema理解**：将数据库Schema信息注入Prompt，帮助模型理解表结构
4. **SQL审查**：关键操作（DELETE/UPDATE）需人工确认
5. **Fallback机制**：NL2SQL失败时，转为知识图谱Cypher查询

**Prompt模板示例：**

```
你是一个SQL生成助手。根据用户问题和数据库Schema，生成正确的SQL查询。

数据库Schema：
{schema_description}

用户问题：{user_question}

要求：
1. 只返回SELECT查询，禁止DELETE/UPDATE/INSERT
2. 使用标准SQL语法
3. 添加适当的WHERE条件过滤
4. 使用DATE_FORMAT处理日期字段

SQL：
```

### 6.2 RAG检索增强生成

RAG（Retrieval-Augmented Generation）用于安全知识问答，通过向量检索召回相关知识，再由LLM生成答案。

**处理流程：**

1. Query Understanding：意图识别、关键词提取、查询扩展
2. 向量检索：Milvus中Top-K相似文档召回
3. 知识图谱增强：Neo4j关联概念和法规引用
4. 答案生成：LLM整合检索结果，生成结构化答案

### 6.3 计算机视觉实现

计算机视觉模块负责监控视频的智能分析，实现人脸识别、安全帽检测、反光衣检测等功能。

**技术选型：**

| 功能 | 模型 | 说明 |
|------|------|------|
| 目标检测 | YOLOv8 | 检测人员、安全帽、反光衣位置 |
| 人脸识别 | ArcFace / InsightFace | 提取人脸特征向量，实现身份识别 |
| 分类识别 | ResNet / EfficientNet | 判断安全帽佩戴、反光衣穿着 |

## 8. 安全与性能

### 8.1 安全设计

系统安全设计遵循等保2.0要求，从物理安全、网络安全、主机安全、应用安全、数据安全五个层面进行防护。

**安全措施：**

- **私有化部署**：LLM模型和数据全部部署在内网，数据不出境
- **数据加密**：敏感数据（人脸、体检报告）加密存储
- **访问控制**：基于RBAC的权限管理，最小权限原则
- **审计日志**：全量操作日志记录，支持追溯审计
- **SQL注入防护**：NL2SQL结果审查，禁止危险操作

### 8.2 性能优化

系统性能优化从数据库、缓存、异步处理等多个维度进行，确保高并发场景下的稳定运行。

**优化策略：**

| 优化维度 | 具体措施 |
|----------|----------|
| 数据库 | MySQL读写分离、分库分表、索引优化 |
| 缓存 | Redis多级缓存，热点数据预热 |
| 异步处理 | 报告生成、监控识别采用异步队列 |
| LLM优化 | 模型量化、批处理、流式输出 |
| 向量检索 | Milvus索引优化，Top-K限制 |

## 9. 实施计划

### 9.1 实施阶段划分

项目实施分为四个阶段，采用敏捷开发模式，每个阶段交付可用的功能模块。

| 阶段 | 功能模块 | 周期 | 交付物 |
|------|----------|------|--------|

### 9.2 关键里程碑

- **M1（第1月）**：四库架构搭建完成，基础数据导入
