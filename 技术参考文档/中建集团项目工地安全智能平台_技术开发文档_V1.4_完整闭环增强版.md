# 1. 项目概述

## 1.1 项目背景

中建集团项目数量多、地域分布广、参建单位复杂、分包层级多、工人流动性强，施工现场安全管理面临以下问题：

1. 隐患数据分散，整改闭环过程不透明；
2. 各项目风险状态难以横向比较；
3. 分包商跨项目安全履约能力缺少统一评价；
4. 工人安全考核、违规行为、体检健康和作业适配数据未形成持续画像；
5. 设备/机械、进度压力、环境监测、安全投入和管理人员配置等系统性风险因素未被统一纳入风险模型；
6. 事故案例复用不足，难以反哺风险预测、培训出题和事故归因；
7. 传统系统多能记录“发生了什么”，但对“为什么发生”“哪里可能出问题”“应该先管什么”支持不足。

因此，本项目拟通过大语言模型 LLM、智能问数引擎 NL2SQL、知识图谱、向量知识库、Redis 缓存、风险评分、贝叶斯归因、多 Agent 协同等技术，构建面向施工安全管理的智能化平台，实现从风险识别、隐患整改、精准培训、分包商评价、事故归因到管理决策的闭环。

## 1.2 项目定位

本项目定位为：

> 面向中建集团项目工地安全管理的智能体协同平台，以项目、工人、分包商三类安全风险画像为核心，以四库协同为数据底座，以多 Agent 为业务执行单元，实现风险识别、智能问数、隐患整改、精准培训、事故归因、分包商评价、报告生成和动态预警的一体化闭环管理。

## 1.3 建设范围

| 对象 | 是否独立画像 | 说明 |
|---|---:|---|
| 项目 | 是 | 形成项目安全风险画像，用于集团、工程局、区域公司、项目部多级风险管控 |
| 工人 | 是 | 形成个人安全风险画像，用于培训、准入、提醒、作业适配和复评 |
| 分包商 | 是 | 形成单位安全风险画像，用于准入、履约、约谈、整改、评价和清退建议 |
| 班组 | 否 | 不独立画像，仅作为工人归属、分包商管理、隐患聚合和责任追踪维度 |
| 设备 | 否 | 不独立作为画像主体，但作为项目画像和分包商画像的重要风险源 |
| 作业区域 | 否 | 不独立画像，但用于风险热力图和隐患空间定位 |
| 事故案例 | 否 | 作为算法验证、归因分析、培训出题和整改建议的数据资产 |

## 1.4 核心价值

1. **集团管理价值**：统一掌握各项目、各分包商风险态势，识别重点项目、重点区域、重点单位。
2. **项目管理价值**：识别现场重大隐患、高危作业、设备机械、进度压力、环境异常和人员配置风险。
3. **工人管理价值**：基于安全考核、违规行为、作业资质、年龄适配和健康适配进行精准培训和作业适配提醒。
4. **分包商管理价值**：形成跨项目、跨周期的分包商安全履约档案，为准入、评价、约谈、限制和清退提供依据。
5. **技术管理价值**：通过四库协同与多 Agent 协作，使系统既能查数、问答，也能预警、解释、归因、整改和生成报告。
6. **闭环管理价值**：构建“画像识别风险—Agent 生成建议—流程派单整改—培训复评—风险回落—案例沉淀—模型校准”的完整闭环。

# 2. 建设目标与设计原则

## 2.1 建设目标

平台建设目标包括：

1. 建立覆盖项目、工人、分包商三类主体的安全风险画像体系。
2. 将隐患整改、高危作业、设备机械、环境监测、进度压力、安全投入、应急管理和管理人员配置纳入项目风险评价。
3. 将资质合规、所属工人风险、隐患整改、违规行为、设备管理、安全投入、应急能力、管理人员配置和事故信用纳入分包商风险评价。
4. 将安全考核成绩、违规行为、作业资质、年龄适配、体检健康适配和作业场景修正纳入工人风险评价。
5. 建立事故案例库，用于案例检索、场景化培训、贝叶斯先验构建、模型回测和权重校准。
6. 建设智能问数 Agent，实现自然语言查询项目风险、工人风险、分包商风险、隐患整改和设备状态。
7. 建设隐患整改 Agent，实现隐患分类、定级、责任识别、整改建议、期限建议、复查与闭环。
8. 建设设备安全 Agent、环境监测 Agent、进度压力 Agent、安全投入分析 Agent、应急管理 Agent 和管理配置核验 Agent。
9. 建设报告生成 Agent，自动生成项目风险报告、分包商评价报告、工人高风险分析报告、事故归因报告和集团风险态势报告。
10. 建设风险预警 Agent，对高风险项目、高风险工人、高风险分包商、超期设备、异常环境和赶工状态进行动态预警。
11. 建设场景化出题 Agent，根据工人画像、事故案例、近期隐患和当前作业生成个性化培训题。
12. 建设贝叶斯事故归因模型，对事故类型、风险因素贡献度和管控优先级进行概率推理。
13. 建立模型治理机制，实现权重版本管理、人工复核、偏差检测、审计留痕和持续校准。

## 2.2 设计原则

### 2.2.1 三类主体，分层管控

- 项目画像服务于项目群风险排序、资源调度和督办管理；
- 工人画像服务于作业准入、精准培训、现场提醒和个人复评；
- 分包商画像服务于安全履约评价、单位约谈、准入决策和跨项目风险识别。

### 2.2.2 班组不独立画像，但保留组织穿透

班组不形成独立画像档案，但必须保留在组织关系中，用于：

1. 工人归属；
2. 隐患责任聚合；
3. 分包商管理穿透；
4. 项目风险定位；
5. 事故调查链路还原；
6. 统计下钻与责任分析。

### 2.2.3 评分不是惩罚，而是风险管理

风险画像主要用于：

- 提醒；
- 培训；
- 复核；
- 作业适配；
- 资源倾斜；
- 隐患治理；
- 事故预防。

不应将模型评分作为直接处罚、清退或岗位调整的唯一依据。

### 2.2.4 人、机、环、管、投入、进度、应急全覆盖

施工事故通常不是单一因素导致，因此项目画像和分包商画像必须覆盖：

```text
人：工人行为、培训、资质、管理人员配置
机：设备状态、维保、检验、安拆
环：天气、基坑监测、周边环境、扬尘噪声
管：隐患整改、制度执行、作业审批、分包管理
投入：安全费用、PPE、防护设施、设备安全投入
进度：赶工期、夜间施工、交叉作业、关键节点压力
应急：预案、演练、物资、上报和复盘
```

### 2.2.5 年龄与健康数据作为作业适配因子

年龄和体检健康状况不应简单作为个人扣分项，应结合岗位、工种和作业场景判断是否适合高处、夜间、重体力、有限空间、机械操作等作业。

### 2.2.6 强规则优先于普通权重

对于重大事故隐患、无证特种作业、设备超期未检仍使用、危大工程未审批施工、重大隐患超期未闭环等场景，应直接触发高等级预警，而不是仅通过权重缓慢加分。

### 2.2.7 可解释、可追溯、可校准

每一个风险分和预警结果均应说明：

- 数据来源；
- 指标贡献；
- 触发规则；
- 关联对象；
- 推荐动作；
- 人工复核状态；
- 模型版本。

# 4. 三类安全风险画像总体设计

## 4.1 画像对象

```text
安全风险画像体系
├── 项目安全风险画像
│   ├── 隐患整改风险
│   ├── 高危作业风险
│   ├── 设备机械风险
│   ├── 施工阶段/进度压力风险
│   ├── 环境监测风险
│   ├── 分包商传导风险
│   ├── 现场行为风险
│   ├── 安全投入保障
│   ├── 管理人员配置
│   └── 应急管理能力
│
├── 工人安全风险画像
│   ├── 安全考核风险
│   ├── 违规行为风险
│   ├── 作业资质风险
│   ├── 年龄作业适配
│   ├── 体检健康适配
│   └── 当前作业场景修正
│
└── 分包商安全风险画像
    ├── 资质准入合规
    ├── 人员管理风险
    ├── 隐患整改表现
    ├── 违规行为表现
    ├── 设备机械管理能力
    ├── 管理人员配置
    ├── 安全投入兑现
    ├── 应急管理能力
    ├── 事故险情与历史信用
    └── 跨项目风险传导
```

## 4.2 风险分与等级

统一采用“风险分”：

- 风险分越高，风险越高；
- 风险分用于预警、排序、趋势分析和管理动作触发；
- 不建议使用“安全分”作为主口径，以避免“低分惩罚化”的理解偏差。

| 风险分 | 风险等级 | 颜色 | 管控动作 |
|---:|---|---|---|
| 0-30 | 低风险 | 绿色 | 常规管理 |
| 31-60 | 中风险 | 黄色 | 加强提醒与跟踪 |
| 61-80 | 高风险 | 橙色 | 重点管控、专项整改、复评 |
| 81-100 | 极高风险 | 红色 | 立即干预、督办、必要时停工或限制作业 |

## 4.3 风险计算总公式

建议采用“基础评分 + 动态修正 + 强规则触发”的组合模型。

```text
最终风险分 = min(100, 基础加权风险分 × 动态修正系数 + 强规则触发分)
```

其中：

1. **基础加权风险分**：由各指标维度按权重计算；
2. **动态修正系数**：用于反映赶工期、极端天气、重大隐患未闭环、交叉作业等短期状态；
3. **强规则触发分**：对重大事故隐患、设备超期未检、无证作业等进行直接加权或直接升档。

## 4.4 动态修正系数建议

| 修正因素 | 建议系数 |
|---|---:|
| 常规状态 | 1.00 |
| 关键节点施工 | 1.05 |
| 夜间施工频繁 | 1.08 |
| 交叉作业强度高 | 1.10 |
| 大风/暴雨/高温等异常天气 | 1.10 |
| 重大隐患未闭环 | 1.20 |
| 事故或严重险情后 7 天内 | 1.25 |
| 多因素叠加上限 | 1.50 |

# 5. 项目安全风险画像设计

## 5.1 项目画像目标

项目画像用于评价单个项目或项目群在某一时间窗口内的综合安全风险，支持集团、工程局、区域公司和项目部进行分层管控。

主要回答：

1. 哪些项目当前风险最高？
2. 哪些项目重大隐患和整改压力最大？
3. 哪些项目存在设备机械风险？
4. 哪些项目处于赶工期、夜间施工或交叉作业高风险状态？
5. 哪些项目环境监测异常？
6. 哪些项目应急准备不足？
7. 哪些项目安全投入和管理配置不足？
8. 哪些项目受高风险分包商传导影响明显？

## 5.2 项目画像推荐维度与权重

建议采用集团级成熟版权重：

| 项目画像维度 | 建议权重 | 说明 |
|---|---:|---|
| 隐患与整改风险 | 22% | 反映现场问题暴露和闭环能力，是最核心结果指标 |
| 高危作业风险 | 16% | 反映危大工程、高处、吊装、动火、有限空间等作业强度 |
| 分包商风险传导 | 14% | 反映高风险分包商对项目整体安全的影响 |
| 设备/机械安全风险 | 12% | 反映塔吊、升降机、吊篮、机械设备等重大风险源 |
| 施工阶段与进度压力 | 10% | 反映赶工期、夜间施工、交叉作业、关键节点压力 |
| 环境监测与外部条件 | 8% | 反映天气、基坑、沉降、水位、周边环境等影响 |
| 现场行为风险 | 8% | 反映 PPE、违章作业、视频 AI 告警等现场行为 |
| 管理人员配置与履职 | 6% | 反映安全员、项目经理、总工和关键岗位到岗情况 |
| 安全投入保障 | 4% | 反映安全费用、PPE、防护设施和设备安全投入 |
| 合计 | 100% |  |

应急管理能力不建议单独占用高权重，而是作为“管理保障能力”中的二级指标，并在重大缺失时使用强规则触发。

## 5.4 项目风险评分公式

```text
项目基础风险分 =

+ 分包商风险传导 × 14%
```

## 5.5 项目强规则触发器

| 基坑监测数据连续异常 | 触发环境风险预警与专家复核 |

| 安全员配置严重不足 | 触发管理配置预警 |
| 安全费用长期未使用且隐患高发 | 触发安全投入分析 |
| 发生事故或严重险情 | 进入事故归因与复盘流程 |

# 6. 工人安全风险画像设计

## 6.1 工人画像目标

工人画像用于识别个人作业安全风险和作业适配状态，主要用于：

1. 作业准入；
2. 精准培训；
3. 班前提醒；
4. 高危作业复核；
5. 违规行为纠偏；
6. 体检与岗位适配提醒；
7. 所属分包商人员管理评价。

## 6.2 工人画像核心维度与权重

| 维度 | 建议权重 | 说明 |
|---|---:|---|
| 安全考核风险 | 25% | 反映安全知识、专项培训、考试成绩和错题情况 |
| 违规行为风险 | 35% | 反映近期违规、严重违规、重复违规和 PPE 不合规 |
| 作业资质风险 | 15% | 反映特种作业证、岗位资质、证书有效期 |
| 体检健康适配风险 | 10% | 判断是否存在职业禁忌或作业限制 |
| 年龄作业适配风险 | 5% | 不单独扣分，仅结合岗位和作业强度使用 |
| 当前作业场景修正 | 10% | 高处、临电、吊装、夜间、有限空间等场景修正 |
| 合计 | 100% |  |

## 6.3 工人风险评分公式

```text
工人基础风险分 =
安全考核风险 × 25%
+ 违规行为风险 × 35%
+ 作业资质风险 × 15%
+ 体检健康适配风险 × 10%
+ 年龄作业适配风险 × 5%
+ 当前作业场景修正 × 10%

工人最终风险分 =
min(100, 工人基础风险分 × 当前项目/作业修正系数 + 强规则触发分)
```

## 6.4 年龄与健康数据使用边界

年龄和体检健康状况不能作为简单歧视性评价指标，应作为“作业适配因子”。

| 数据 | 合理用途 | 不建议用途 |
|---|---|---|
| 年龄 | 高处、夜间、重体力、连续作业适配提醒 | 简单按年龄高低扣分 |
| 体检有效期 | 作业准入核验 | 公开健康明细 |
| 职业禁忌 | 限制对应风险作业 | 作为处罚依据 |
| 血压异常 | 高处、夜间、重体力作业复核 | 直接判定不合格 |
| 眩晕/癫痫风险 | 高处、机械、吊装作业限制 | 非授权人员查看详情 |
| 心肺异常 | 有限空间、重体力作业适配提醒 | 直接作为排名依据 |

## 6.5 工人强规则触发器

| 触发条件 | 建议动作 |
|---|---|
| 特种作业证过期或无证 | 禁止从事对应特种作业 |
| 体检过期 | 暂停高危作业准入，完成体检后复评 |
| 存在明确职业禁忌 | 禁止对应高风险作业 |
| 30 天内严重违规 ≥ 1 次 | 风险等级至少提升至高风险 |
| 30 天内重复同类违规 ≥ 3 次 | 推送专项培训并通知安全员 |
| 安全考核不合格 | 限制参与高危作业，完成补训后复评 |
| 高处作业中 PPE 不合规 | 立即现场提醒并纳入隐患闭环 |
| 事故或险情直接关联 | 进入复训、复核和事故复盘流程 |

## 6.6 工人画像标签

```text
风险标签：
- 多次违规
- 严重违规
- 培训不合格
- 特种作业证待核验
- 体检过期
- 作业适配待复核
- 高处作业重点关注
- 夜间作业疲劳风险
- PPE 不合规高发

能力标签：
- 安全考核优秀
- 专项培训已通过
- 特种作业持证
- 主动上报隐患
- 无违规记录

管理建议标签：
- 需补训
- 需复检
- 需班前重点提醒
- 需限制高危作业
- 需安全员现场复核
```

# 7. 分包商安全风险画像设计

## 7.1 分包商画像目标

分包商画像用于评价参建单位安全履约能力和跨项目风险表现，支持：

1. 准入审核；
2. 安全履约评价；
3. 高风险单位约谈；
4. 分包商专项整改；
5. 限制承接高危作业；
6. 跨项目风险传导识别；
7. 合作评价和清退建议。

## 7.2 分包商画像推荐维度与权重

| 违规行为与现场表现 | 12% | 所属工人违规、违章指挥、PPE 不合规 |
| 设备/机械管理能力 | 10% | 自有/租赁设备合格率、维保能力、安拆资质 |
| 管理人员配置与履职 | 8% | 分包负责人、安全员、技术员到岗与持证 |
| 安全投入兑现 | 5% | PPE、防护设施、设备维保投入落实 |
| 应急管理能力 | 5% | 预案、演练、物资、上报及时性 |
| 事故险情与历史信用 | 5% | 历史事故、处罚、投诉、履约信用 |
| 合计 | 100% |  |

## 7.3 分包商风险评分公式

```text
分包商基础风险分 =
资质与准入合规 × 15%
+ 人员资质与工人风险 × 18%
+ 隐患与整改表现 × 22%
+ 违规行为与现场表现 × 12%
+ 设备/机械管理能力 × 10%
+ 管理人员配置与履职 × 8%
+ 安全投入兑现 × 5%
+ 应急管理能力 × 5%
+ 事故险情与历史信用 × 5%

分包商最终风险分 =
min(100, 分包商基础风险分 × 项目作业风险修正系数 + 强规则触发分)
```

| 体检有效率 | 所属工人体检有效比例 |
| 人员流动率 | 高频流动会增加管理风险 |
| 新进场人员比例 | 新工人多时培训和交底压力上升 |

### 7.4.3 隐患与整改表现

## 7.5 分包商强规则触发器

| 触发条件 | 建议动作 |
|---|---|
| 安全生产许可证失效 | 禁止准入或立即复核 |
| 专业资质与承包内容不匹配 | 限制对应作业 |
| 所属工人存在无证特种作业 | 约谈并限制相关作业 |
| 重大隐患超期未整改 | 分包商风险等级提升至高风险 |
| 同类隐患跨项目重复出现 | 纳入集团级重点关注 |
| 设备超期未检仍使用 | 停用设备并启动设备安全专项检查 |
| 分包负责人长期不到岗 | 触发管理履职预警 |
| 发生责任事故 | 进入事故复盘和履约评价流程 |
| 高风险工人占比持续升高 | 要求专项培训和人员调整 |

# 8. 三类画像风险传导与闭环机制

## 8.1 风险传导逻辑

```text
工人风险
  ↓ 聚合
分包商人员管理风险
  ↓ 传导
项目分包商风险
  ↓ 影响
项目总体风险

项目高危作业、设备、进度、环境状态
  ↓ 放大
工人当前作业场景风险
  ↓ 反馈
分包商履约与人员管理风险

项目管理配置、安全投入、应急能力
  ↓ 影响
隐患闭环能力、设备安全水平、环境响应能力
  ↓ 反映
项目综合风险变化
```

## 8.2 工人到分包商传导

| 指标 | 公式 |
|---|---|
| 高风险工人占比 | 高风险工人数 / 所属工人总数 |
| 培训不合格率 | 培训不合格工人数 / 应培训工人数 |
| 严重违规率 | 严重违规次数 / 出勤人日 |
| 证书异常率 | 证书异常人数 / 特种作业人数 |
| 体检异常待复核率 | 待复核人数 / 所属工人数 |

## 8.3 分包商到项目传导

| 指标 | 公式 |
|---|---|
| 高风险分包商占比 | 高风险分包商数量 / 项目分包商总数 |
| 分包商整改超期率 | 分包商责任隐患超期数 / 分包商责任隐患总数 |
| 分包商重大隐患贡献率 | 分包商责任重大隐患数 / 项目重大隐患总数 |
| 分包商设备风险贡献 | 分包商设备风险分加权平均 |
| 分包商人员风险贡献 | 分包商高风险工人占比加权平均 |

## 8.4 项目到工人和分包商的反向修正

同一工人在普通项目和高风险项目中的动态风险不同。

```text
工人动态风险 = 个人基础风险 × 当前项目风险修正系数 × 当前作业场景修正系数
```

同一分包商在不同项目中的风险也应区分：

```text
分包商项目内风险 = 分包商基础风险 × 当前项目作业强度修正 × 当前设备/环境/进度修正
```

## 8.5 完整闭环

```text
数据采集
  ↓
三类画像计算
  ↓
高风险识别
  ↓
Agent 解释风险原因
  ↓
触发预警/督办/整改/培训/限制作业
  ↓
责任主体执行
  ↓
整改、培训、复查结果回写
  ↓
画像重新计算
  ↓
风险趋势回落或升级
  ↓
报告生成与管理复盘
  ↓
事故案例和治理经验沉淀
  ↓
模型回测与权重校准
```

# 12. 事故案例库与算法验证机制

## 12.1 事故案例库用途

1. 验证画像评分是否能提前识别高风险对象；
2. 优化权重和强规则；
3. 为贝叶斯网络提供先验概率；
4. 为隐患整改 Agent 提供类似案例；
5. 为场景化出题 Agent 提供真实案例题材；
6. 为报告生成 Agent 提供事故复盘素材；
7. 为集团安全管理提供经验沉淀。

## 12.2 案例标签体系

| 标签类别 | 标签示例 |
|---|---|
| 事故类型 | 高处坠落、物体打击、触电、坍塌、机械伤害、火灾、中毒窒息 |
| 作业场景 | 高处作业、临电、吊装、动火、有限空间、深基坑、模板支撑 |
| 直接原因 | PPE不规范、防护缺失、设备故障、违章操作、环境异常 |
| 间接原因 | 培训不足、交底不到位、监管缺位、赶工期、分包管理弱、安全投入不足 |
| 涉及主体 | 项目、分包商、工人、设备、区域、管理人员 |
| 严重程度 | 近失事件、一般险情、严重险情、一般事故、较大事故、重大事故 |
| 可预警指标 | 重复隐患、整改超期、违规高发、培训不合格、设备超期、环境异常 |
| 防范措施 | 技术措施、管理措施、培训措施、设备措施、应急措施 |

## 12.3 历史回测方法

```text
事故发生日 T
  ↓
截取 T-7、T-30、T-90 的历史数据
  ↓
使用当时可获得数据计算三类画像风险
  ↓
判断事故相关项目/工人/分包商是否进入高风险名单
  ↓
统计命中率、漏报率、误报率和提前量
```

## 12.4 算法评估指标

| 指标 | 说明 |
|---|---|
| 高风险命中率 | 事故前被识别为高风险的比例 |
| 漏报率 | 事故前未识别风险的比例 |
| 误报率 | 被判高风险但未发生明显问题的比例 |
| Top-K 命中率 | 风险排名前 K 中命中事故主体比例 |
| 预警提前量 | 提前多少天发现风险 |
| 整改有效性 | 预警后整改是否带来风险分下降 |
| 指标贡献稳定性 | 不同案例中核心指标贡献是否稳定 |

# 13. 贝叶斯归因与风险预测模型

## 13.1 模型定位

画像评分回答：

> 谁风险高？

贝叶斯归因回答：

> 为什么风险高？如果发生事故，最可能的原因是什么？优先管控哪个因素？

## 13.2 节点设计

| 类别 | 节点示例 |
|---|---|
| 人 | 培训不足、违规操作、疲劳作业、健康不适配、无证作业 |
| 机 | 设备故障、维保缺失、检测超期、防护装置失效 |
| 料 | 易燃材料堆放、材料堆码不稳、吊索具不合格 |
| 法 | 方案缺失、交底不到位、作业票不规范、审批缺失 |
| 环 | 大风、暴雨、高温、夜间照明不足、基坑变形、交叉作业 |
| 管 | 监管缺位、整改不闭环、分包管理弱、赶工期、安全投入不足 |
| 应急 | 预案缺失、演练不足、物资不足、上报不及时 |
| 结果 | 高处坠落、触电、物体打击、坍塌、火灾、机械伤害 |

## 13.3 与三类画像联动

| 画像 | 输入变量 |
|---|---|
| 项目画像 | 高危作业强度、整改超期、设备风险、环境风险、进度压力 |
| 工人画像 | 培训不足、违规行为、健康适配、疲劳风险、无证作业 |
| 分包商画像 | 管理薄弱、人员高风险占比、整改能力差、设备管理弱、历史事故 |

## 13.4 输出结果

1. 事故类型概率；
2. 关键风险因素排序；
3. 原因贡献度；
4. 风险传播路径；
5. 管控措施优先级；
6. 建议整改动作；
7. 需要人工复核的证据项。

# 15. 安全、合规与模型治理

## 15.1 数据权限

| 用户角色 | 可访问范围 |
|---|---|
| 集团管理人员 | 全集团项目和分包商统计，可查看脱敏工人画像 |
| 工程局/区域管理人员 | 所属范围内项目、分包商和脱敏工人统计 |
| 项目经理 | 本项目数据 |
| 项目安全员 | 本项目工人、隐患、设备、分包商画像 |
| 分包商负责人 | 本单位在本项目的相关数据，不可查看其他单位 |
| 工人本人 | 可查看个人培训、考核、整改建议，不展示敏感评分细节 |
| 系统管理员 | 管理系统配置，不默认拥有业务敏感数据查看权限 |

## 15.2 敏感数据合规边界

1. 年龄、体检健康、证件信息属于敏感或准敏感数据，应最小化采集；
2. 健康明细只用于作业适配和准入复核，不向无关角色展示；
3. 涉及作业限制、岗位调整、分包商清退等动作必须人工确认；
4. 工人和分包商应有申诉、复核和数据纠错机制；
5. 模型输出应避免歧视性表述；
6. 分数、标签和建议应有可解释依据；
7. 重要模型决策应记录数据快照和模型版本。

## 15.3 模型治理

| 治理项 | 要求 |
|---|---|
| 版本管理 | 每次权重调整形成模型版本 |
| 审计留痕 | 每次评分和预警保留数据快照 |
| 人工复核 | 高风险结论、作业限制、停工建议、清退建议需人工确认 |
| 偏差检测 | 定期检查是否对年龄、工种、地区、分包类型产生不合理偏差 |
| 回测验证 | 定期用事故案例库进行模型效果评估 |
| 可解释输出 | 所有高风险画像必须给出原因和建议 |
| 灰度发布 | 新权重或新规则先在试点项目灰度验证 |
| 失效监控 | 模型命中率下降时触发复盘 |

## 15.4 NL2SQL 安全控制

1. 只允许 SELECT 查询；
2. 自动注入用户权限过滤；
3. 高敏字段脱敏；
4. 禁止查询个人健康明细，除非角色授权；
5. SQL 执行前进行白名单校验；
6. 查询结果记录审计日志；
7. 指标口径来自指标语义层；
8. 大范围导出需要审批或脱敏。

## 18.2 术语表

| 术语 | 说明 |
|---|---|
| LLM | 大语言模型，用于自然语言理解、生成、解释和推理 |
| NL2SQL | 自然语言转 SQL，用于智能问数 |
| RAG | 检索增强生成，用于结合知识库回答问题 |
| Agent | 智能体，能够理解任务、调用工具、生成结果 |
| 安全风险画像 | 对项目、工人、分包商的风险状态进行结构化、标签化、评分化描述 |
| 贝叶斯归因 | 基于概率推理分析事故原因和风险因素贡献度 |
| 强规则 | 一旦触发即直接升级风险或限制操作的规则 |
| 作业适配因子 | 判断某个工人是否适合某类作业的辅助因子 |
| 动态修正系数 | 用于反映天气、赶工期、交叉作业等短期风险变化的系数 |
| 风险传导 | 工人、分包商、项目之间风险相互影响的机制 |
