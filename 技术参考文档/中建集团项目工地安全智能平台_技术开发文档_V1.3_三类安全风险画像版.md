# 中建集团项目工地安全智能平台

## 技术开发文档（V1.3 三类安全风险画像版）

**基于大语言模型、NL2SQL、四库协同与三类安全风险画像的施工安全智能管控平台**

版本：V1.3  
日期：2026年5月  
适用对象：中建集团信息化部门、安全管理部门、项目管理团队、平台研发团队、数据治理团队

---

## 修订说明

本版本在前序方案基础上，对“安全风险画像体系”进行重新调整：平台不再将“班组”作为独立画像对象，而是聚焦 **项目画像、工人画像、分包商画像** 三类核心主体。班组仍保留在组织关系、隐患归属、责任追踪和统计分析中，但作为项目、工人、分包商画像的关联维度和聚合维度，不单独形成画像档案。

本版本重点修改如下：

1. 将画像体系调整为“三类画像”：项目安全风险画像、工人安全风险画像、分包商安全风险画像。
2. 明确班组不作为独立画像对象，但作为关系图谱、隐患归集、工人归属、分包商过程表现的重要关联节点。
3. 补充项目画像指标体系，用于评估各项目整体安全风险、重大隐患压力、整改闭环能力、分包商风险传导、作业阶段风险和事故苗头。
4. 补充工人画像指标体系，重点使用安全考核成绩、违规行为、年龄因素、体检健康状况，并引入岗位、工种、作业场景和强规则触发器。
5. 补充分包商画像指标体系，用于评价资质合规、人员管理、隐患整改、违规行为、事故记录、项目履约和安全管理能力。
6. 补充三类画像之间的风险传导机制：工人风险向分包商聚合，分包商风险向项目传导，项目风险反向影响工人和分包商的管理策略。
7. 补充事故案例库导入、算法验证、权重校准、贝叶斯归因与模型评估机制。
8. 补充 MySQL、Neo4j、Milvus、Redis 在画像系统中的数据分工、表结构与接口设计。
9. 补充 Agent 联动方式，将画像结果接入智能问数、隐患整改、报告生成、风险预警、场景化出题、事故归因等 Agent。
10. 补充安全合规原则，尤其是年龄与健康数据的合规使用边界，避免简单歧视性评分。

# 1. 项目概述

## 1.1 项目背景

中建集团项目数量多、地域分布广、参建单位复杂、工人流动性强，施工现场安全管理面临隐患数据分散、整改闭环不透明、分包商风险难以横向比较、工人个人安全状态难以持续跟踪、事故案例复用不足等问题。

传统安全管理系统多以台账、流程和报表为主，能够记录“发生了什么”，但对“为什么发生”“下一步哪里可能出问题”“哪些项目、工人、分包商需要重点管控”的支持不足。因此，本项目拟通过大语言模型、智能问数、知识图谱、向量知识库、风险评分和贝叶斯归因等技术，构建面向施工安全管理的智能平台。

## 1.2 项目定位

本项目定位为：

> 面向项目工地安全管理的智能体协同平台，以项目、工人、分包商三类安全风险画像为核心，以四库协同为数据底座，以多 Agent 为业务执行单元，实现风险识别、隐患整改、智能问数、报告生成、精准培训、事故归因和风险预警的一体化闭环管理。

## 1.3 建设范围

本平台覆盖以下业务对象：

| 对象 | 是否独立画像 | 说明 |
|---|---:|---|
| 项目 | 是 | 形成项目安全风险画像，用于集团、区域、公司、项目多级管控 |
| 工人 | 是 | 形成个人安全风险画像，用于培训、准入、提醒、作业适配 |
| 分包商 | 是 | 形成单位安全风险画像，用于准入、履约、约谈、评价、清退建议 |
| 班组 | 否 | 不独立画像，仅作为工人归属、分包商管理、隐患聚合和责任追踪维度 |

## 1.4 核心价值

1. **集团层面**：掌握各项目、各分包商安全风险态势，识别重点项目和高风险单位。
2. **项目层面**：识别现场重点风险、重大隐患、超期整改、重复隐患和高风险作业。
3. **工人层面**：基于安全考核、违规行为、年龄、体检健康状况和作业场景进行风险识别和精准培训。
4. **分包商层面**：形成跨项目、跨周期的分包商安全履约档案，为准入和评价提供依据。
5. **智能化层面**：将画像结果接入多 Agent，让系统不仅能“查数据”，还能“给建议、促整改、做预警、出报告”。

# 2. 建设目标与设计原则

## 2.1 建设目标

平台建设目标包括：

1. 建立覆盖项目、工人、分包商的三类安全风险画像体系。
2. 通过 MySQL、Neo4j、Milvus、Redis 四库协同，打通结构化数据、关系数据、知识数据和缓存数据。
3. 建设智能问数 Agent，实现自然语言查询隐患、整改、培训、评分、项目风险和分包商风险。
4. 建设隐患整改 Agent，实现隐患分类、定级、责任识别、整改建议、复查和闭环。
5. 建设报告生成 Agent，自动生成项目日报、周报、月报、分包商评价报告和画像分析报告。
6. 建设风险预警 Agent，对高风险项目、高风险工人、高风险分包商进行动态预警。
7. 建设场景化出题 Agent，根据工人画像、事故案例和近期隐患生成个性化安全培训题。
8. 建设事故归因 Agent，结合事故案例库、知识图谱和贝叶斯网络分析事故原因。
9. 建立事故案例验证机制，用历史事故/险情案例回测画像算法的合理性。

## 2.2 设计原则

### 2.2.1 三类主体，分层管控

项目、工人、分包商分别对应不同管理层级和业务动作：

- 项目画像服务于项目群风险管控和资源调度；
- 工人画像服务于作业准入、精准培训和现场提醒；
- 分包商画像服务于分包履约评价、准入决策和单位约谈。

### 2.2.2 班组不独立画像，但不可丢失

不建议完全删除班组概念。班组虽然不做独立画像，但仍应作为重要关系节点保留在数据模型中，用于：

1. 工人归属关系；
2. 隐患责任聚合；
3. 分包商管理穿透；
4. 项目风险定位；
5. 事故调查中的组织链路还原。

### 2.2.3 评分不是惩罚，而是风险管理

安全风险画像不应简单用于处罚个人或单位，而应主要用于：

- 精准培训；
- 风险提示；
- 作业适配；
- 管理干预；
- 隐患预防；
- 资源倾斜；
- 事故复盘。

### 2.2.4 年龄与健康数据应作为作业适配因子

年龄和体检健康状况不建议直接作为扣分项，而应作为“作业适配因子”和“风险提示因子”。例如高血压、眩晕、心肺异常等体检结果，应主要用于判断是否适合高处作业、夜间作业、重体力作业、有限空间作业等，而不是简单降低个人综合评价。

### 2.2.5 模型可解释、可追溯、可校准

每一个风险评分都应能解释：

- 评分依据是什么；
- 数据来自哪里；
- 哪些指标影响最大；
- 近期风险为什么上升；
- 建议采取什么管理动作；
- 是否可以人工复核和申诉。

# 3. 总体架构设计

## 3.1 总体架构

平台采用“数据采集层、四库数据层、智能能力层、Agent 编排层、业务应用层、用户交互层”的六层架构。

```text
┌──────────────────────────────────────────────┐
│ 用户交互层：Web端、移动端、企业微信、驾驶舱大屏 │
├──────────────────────────────────────────────┤
│ 业务应用层：三类画像、问数、整改、报告、培训、预警 │
├──────────────────────────────────────────────┤
│ Agent编排层：主控Agent + 专项Agent + 工具调用层 │
├──────────────────────────────────────────────┤
│ 智能能力层：LLM、NL2SQL、RAG、KG、贝叶斯、CV │
├──────────────────────────────────────────────┤
│ 四库数据层：MySQL + Neo4j + Milvus + Redis │
├──────────────────────────────────────────────┤
│ 数据采集层：实名制、隐患、巡检、视频、设备、培训、事故 │
└──────────────────────────────────────────────┘
```

## 3.2 技术栈建议

| 模块 | 技术选型 | 说明 |
|---|---|---|
| 大语言模型 | Qwen、DeepSeek、GLM、私有化大模型 | 用于问答、报告、解释、归因、出题 |
| NL2SQL | SQLCoder、Qwen-Coder、领域微调模型 | 用于自然语言问数 |
| Agent 编排 | LangGraph、LangChain、Dify、FastAPI 自研编排 | 支持多智能体任务路由 |
| 关系数据库 | MySQL 8.0 | 结构化业务事实主库 |
| 图数据库 | Neo4j 5.x | 项目、分包商、工人、隐患、事故关系图谱 |
| 向量数据库 | Milvus 2.4+ | 安全知识库、事故案例、整改案例、行为记忆向量 |
| 缓存 | Redis 7.x Cluster | 会话、热点指标、画像结果、任务状态缓存 |
| 后端服务 | FastAPI / Spring Boot | 业务服务、接口服务、数据服务 |
| 前端 | Vue3 + Element Plus | 管理端与驾驶舱 |
| BI 可视化 | ECharts / Superset / FineBI | 风险大屏与统计分析 |
| 规则引擎 | Drools / 自研规则引擎 | 强规则、阈值预警、准入控制 |
| 计算任务 | Airflow / DolphinScheduler | 定时画像计算、案例回测、报表生成 |

# 4. 三类安全风险画像体系

## 4.1 画像对象

本平台画像体系包括三类：

```text
安全风险画像体系
├── 项目安全风险画像
│   ├── 项目总体风险
│   ├── 隐患与整改风险
│   ├── 高危作业风险
│   ├── 分包商传导风险
│   ├── 事故苗头风险
│   └── 阶段性趋势预警
│
├── 工人安全风险画像
│   ├── 安全考核风险
│   ├── 违规行为风险
│   ├── 年龄适配风险
│   ├── 体检健康适配风险
│   ├── 作业场景风险
│   └── 个性化培训建议
│
└── 分包商安全风险画像
    ├── 资质合规风险
    ├── 人员管理风险
    ├── 隐患整改风险
    ├── 违规行为风险
    ├── 事故与险情风险
    └── 履约评价风险
```

## 4.2 班组处理方式

班组不做独立画像，但保留以下数据功能：

| 用途 | 说明 |
|---|---|
| 组织关系 | 工人属于班组，班组属于分包商 |
| 责任归属 | 隐患、整改、违章可记录到班组，但不形成独立画像页 |
| 聚合统计 | 项目和分包商画像可按班组维度下钻查看 |
| 风险定位 | 当某类风险集中于某班组时，作为原因解释，不单独评分 |
| 事故复盘 | 用于还原事故前的组织管理链条 |

建议表述为：

> 平台不建设独立班组画像，但建设班组关联分析能力。

这样既简化画像对象，又不会损失现场管理的组织穿透能力。

## 4.3 画像计算总流程

```text
多源数据采集
  ↓
数据清洗与统一ID映射
  ↓
指标标准化
  ↓
强规则识别
  ↓
权重评分计算
  ↓
风险等级判定
  ↓
画像标签生成
  ↓
LLM生成可解释说明
  ↓
预警/整改/培训/报告联动
  ↓
事故案例回测与模型校准
```

## 4.4 风险评分口径

建议统一采用“风险分”而不是“安全分”。

- 风险分越高，风险越高；
- 管控动作更容易与分值联动；
- 与项目风险、分包商风险、事故概率模型更一致。

通用等级建议：

| 风险分 | 风险等级 | 颜色 | 管控动作 |
|---:|---|---|---|
| 0-30 | 低风险 | 绿色 | 常规管理 |
| 31-60 | 中风险 | 黄色 | 加强提醒与跟踪 |
| 61-80 | 高风险 | 橙色 | 重点管控、专项整改 |
| 81-100 | 极高风险 | 红色 | 立即干预、必要时停工或限制作业 |

# 5. 项目安全风险画像设计

## 5.1 项目画像目标

项目安全风险画像用于评估单个项目或项目群在某一时间窗口内的安全风险水平，支持集团、局、公司、项目部多层级安全管理。

主要回答：

1. 哪些项目当前风险最高？
2. 哪些项目重大隐患未闭环？
3. 哪些项目高危作业集中？
4. 哪些项目分包商风险传导明显？
5. 哪些项目事故苗头或重复隐患突出？
6. 哪些项目需要集团或区域重点督办？

## 5.2 项目画像指标体系

建议项目风险画像分为六大维度：

| 维度 | 权重建议 | 指标示例 | 数据来源 |
|---|---:|---|---|
| 基础固有风险 | 15% | 工程类型、规模、高度、深度、复杂度、施工阶段 | 项目主数据、施工组织设计 |
| 隐患与整改风险 | 25% | 隐患数量、重大隐患数、整改超期率、复查不通过率、重复隐患率 | 隐患台账、整改记录 |
| 高危作业风险 | 20% | 危大工程数量、动火作业、吊装作业、深基坑、高处作业、有限空间作业 | 作业票、专项方案、审批系统 |
| 现场行为风险 | 15% | 违规作业次数、视频AI告警、PPE不合规、违章高发区域 | 巡检、视频AI、处罚记录 |
| 分包商传导风险 | 15% | 高风险分包商数量、分包商整改率、分包商事故/险情记录 | 分包商画像、合同、履约数据 |
| 事故苗头与外部环境 | 10% | 近失事件、天气异常、赶工期、夜间施工、交叉作业 | 事故/险情、气象、进度计划 |

## 5.3 项目风险评分公式

```text
项目风险分 = 
基础固有风险 × 15%
+ 隐患与整改风险 × 25%
+ 高危作业风险 × 20%
+ 现场行为风险 × 15%
+ 分包商传导风险 × 15%
+ 事故苗头与外部环境风险 × 10%
+ 强规则加权修正
```

## 5.4 项目强规则触发器

出现以下情况时，应直接提升项目风险等级或触发红色预警：

| 触发条件 | 建议动作 |
|---|---|
| 存在重大隐患超期未闭环 | 项目风险至少提升至高风险 |
| 同一类型重大隐患 30 天内重复出现 | 触发专项治理 |
| 高危作业未审批先施工 | 触发停工核查 |
| 特种设备超期未检仍使用 | 触发红色预警 |
| 高风险分包商承担关键高危作业 | 提醒项目部加强旁站和审批 |
| 发生事故或严重险情 | 进入事故复盘和归因流程 |

## 5.5 项目画像输出内容

项目画像页面建议包括：

1. 项目综合风险分与风险等级；
2. 六大维度雷达图；
3. 最近 7 天、30 天、90 天风险趋势；
4. 重大隐患闭环情况；
5. 高危作业风险清单；
6. 高风险分包商清单；
7. 高风险工人数量与分布；
8. 隐患类型 Top 10；
9. 风险区域热力图；
10. Agent 生成的风险解释和整改建议。

## 5.6 项目画像示例

```text
项目：华东某超高层项目
当前风险等级：高风险（72分）

主要风险原因：
1. 近30天高处作业隐患 18 起，其中 4 起复查未通过；
2. 2 家分包商近期整改超期率超过 30%；
3. 当前处于主体结构施工高峰期，存在吊装、高处、临电交叉作业；
4. 视频AI识别到 PPE 不规范告警 26 次；
5. 近7天连续出现临边防护类重复隐患。

建议管理动作：
1. 对高处作业和临边防护开展专项检查；
2. 约谈整改超期分包商；
3. 对相关工人推送高处作业专项培训题；
4. 将重复隐患纳入项目周例会督办事项。
```

# 6. 工人安全风险画像设计

## 6.1 工人画像目标

工人画像用于识别个人安全风险，不是为了简单处罚，而是用于作业适配、精准培训、风险提醒和现场管理干预。

主要回答：

1. 哪些工人需要重点安全提醒？
2. 哪些工人不适合参与特定高风险作业？
3. 哪些工人近期违规行为上升？
4. 哪些工人安全考核薄弱，需要专项培训？
5. 年龄和体检健康状况是否影响某类作业适配？
6. 工人风险是否与特定项目、分包商、工种、作业场景有关？

## 6.2 工人画像核心维度

你提出的四类维度是合理的，建议表述如下：

| 维度 | 建议定位 | 是否直接扣分 | 说明 |
|---|---|---:|---|
| 安全考核成绩 | 能力认知因子 | 是 | 反映安全知识掌握程度 |
| 违规行为 | 行为风险因子 | 是 | 反映现场实际不安全行为 |
| 年龄 | 作业适配因子 | 谨慎 | 不建议简单扣分，应结合工种和作业场景使用 |
| 体检健康状况 | 健康适配因子 | 谨慎 | 用于职业禁忌和高危作业适配判断 |

建议增加两个修正因子：

| 修正因子 | 作用 |
|---|---|
| 工种/岗位因子 | 不同岗位风险基线不同，如电工、架子工、塔吊司机、焊工风险不同 |
| 作业场景因子 | 高处、临电、动火、吊装、夜间、有限空间等作业场景风险不同 |

## 6.3 工人画像指标体系

| 维度 | 权重建议 | 指标示例 | 数据来源 |
|---|---:|---|---|
| 安全考核风险 | 25% | 最近考试成绩、专项考试成绩、错题率、补考次数、培训缺勤 | 培训系统、考试系统 |
| 违规行为风险 | 40% | 违规次数、严重违规、重复违规、PPE不合规、视频AI告警 | 巡检、隐患、视频AI、处罚记录 |
| 年龄适配风险 | 10% | 年龄段、岗位适配、夜间/高处/重体力作业适配 | 实名制、人员档案 |
| 体检健康适配风险 | 15% | 体检是否有效、职业禁忌、血压/眩晕/心肺异常等作业限制 | 体检系统、健康档案 |
| 作业场景修正 | 10% | 当前是否参与高危作业、连续作业、夜间施工、交叉作业 | 作业票、考勤、门禁 |

## 6.4 工人风险评分公式

```text
工人风险分 = 
安全考核风险 × 25%
+ 违规行为风险 × 40%
+ 年龄适配风险 × 10%
+ 体检健康适配风险 × 15%
+ 作业场景修正风险 × 10%
+ 强规则触发加分
```

其中：

- 安全考核分越低，安全考核风险越高；
- 违规行为以最近 30 天、90 天为主要窗口，近期权重更高；
- 年龄不作为单独歧视性扣分，应结合岗位和作业环境；
- 体检健康异常不直接代表“差”，而是判断是否适合某类作业；
- 高危作业场景会放大已有风险。

## 6.5 年龄因子的合理使用建议

年龄数据应避免简单粗暴地作为扣分项。建议采用“年龄—岗位—作业场景”三者联动方式。

示例：

| 场景 | 处理方式 |
|---|---|
| 普通地面作业 | 年龄影响较低 |
| 高处作业 | 高龄且存在健康异常时提高适配风险 |
| 夜间连续作业 | 年龄较高且连续作业时长过长时提示疲劳风险 |
| 重体力搬运 | 结合体检、工种和作业强度判断 |
| 特种作业 | 以持证、培训、健康适配为主，年龄仅作辅助因子 |

不建议输出“某工人因年龄高所以高风险”这样的表述。建议输出：

> 该工人当前参与高处作业，且体检存在血压异常记录，建议进行作业适配复核。

## 6.6 体检健康状况的合理使用建议

体检健康状况主要用于判断是否存在职业禁忌或作业限制，不建议纳入简单排名。

| 健康数据 | 建议用途 |
|---|---|
| 体检是否有效 | 作为准入强规则 |
| 职业禁忌 | 限制作业类型 |
| 血压异常 | 高处作业、夜间作业、重体力作业适配提醒 |
| 眩晕/癫痫等风险 | 高处、机械、吊装等作业禁忌提醒 |
| 心肺异常 | 重体力、有限空间、长时间作业适配提醒 |
| 听力/视力异常 | 机械操作、指挥、信号工等岗位适配提醒 |

## 6.7 工人强规则触发器

| 触发条件 | 建议动作 |
|---|---|
| 特种作业证过期或无证 | 禁止从事对应特种作业 |
| 体检过期 | 暂停高危作业准入 |
| 存在明确职业禁忌 | 禁止对应高风险作业 |
| 30天内严重违规 ≥ 1 次 | 风险等级至少提升至高风险 |
| 30天内重复同类违规 ≥ 3 次 | 推送专项培训并通知安全员 |
| 安全考核不合格 | 限制参与高危作业，完成补训后复评 |
| 高处作业中出现 PPE 不合规 | 立即现场提醒并纳入隐患闭环 |

## 6.8 工人画像标签

```text
工人画像标签
├── 风险标签
│   ├── 多次违规
│   ├── 严重违规
│   ├── 培训不合格
│   ├── 体检过期
│   ├── 作业适配待复核
│   ├── 高处作业重点关注
│   └── 特种作业证书待核验
│
├── 能力标签
│   ├── 安全考核优秀
│   ├── 专项培训已通过
│   ├── 特种作业持证
│   └── 隐患主动上报
│
└── 管理建议标签
    ├── 需补训
    ├── 需复检
    ├── 需班前重点提醒
    ├── 需限制高危作业
    └── 需安全员复核
```

## 6.9 工人画像输出示例

```text
工人：张某
工种：架子工
所属分包商：某劳务公司
当前风险等级：高风险（76分）

主要原因：
1. 最近 30 天出现 2 次高处作业未规范系挂安全带；
2. 最近一次高处作业专项考试成绩为 68 分，低于合格线；
3. 当前参与外脚手架作业，属于高风险作业场景；
4. 体检记录有效，但存在血压偏高提醒，建议进行高处作业适配复核。

建议动作：
1. 暂停其独立高处作业，完成专项补训后复评；
2. 班前会进行安全带使用重点提醒；
3. 安全员现场复核 PPE 使用情况；
4. 7 天后重新计算画像风险。
```

# 7. 分包商安全风险画像设计

## 7.1 分包商画像目标

分包商画像用于评价参建单位的安全履约能力，支持准入、评价、约谈、整改、资源分配和合作决策。

主要回答：

1. 哪些分包商安全风险高？
2. 哪些分包商隐患整改能力弱？
3. 哪些分包商所属工人违规频发？
4. 哪些分包商跨项目表现持续较差？
5. 哪些分包商可以优先合作？
6. 哪些分包商需要限制高危作业或清退？

## 7.2 分包商画像指标体系

| 维度 | 权重建议 | 指标示例 | 数据来源 |
|---|---:|---|---|
| 资质合规风险 | 15% | 企业资质、安全生产许可证、特种作业人员持证率、安管人员配置 | 资质库、合同系统 |
| 人员管理风险 | 20% | 所属工人高风险比例、培训合格率、体检有效率、人员流动率 | 实名制、工人画像 |
| 隐患整改风险 | 25% | 隐患数、重大隐患数、整改及时率、复查通过率、重复隐患率 | 隐患整改系统 |
| 违规行为风险 | 15% | 所属工人违规次数、严重违规、PPE不合规、视频AI告警 | 巡检、视频AI |
| 事故与险情风险 | 15% | 事故数、近失事件、险情数、事故严重度 | 事故管理系统 |
| 履约与协同风险 | 10% | 安全投入、会议参与、整改配合、投诉、处罚、履约评价 | 项目评价、合同履约 |

## 7.3 分包商风险评分公式

```text
分包商风险分 = 
资质合规风险 × 15%
+ 人员管理风险 × 20%
+ 隐患整改风险 × 25%
+ 违规行为风险 × 15%
+ 事故与险情风险 × 15%
+ 履约与协同风险 × 10%
+ 强规则触发加分
```

## 7.4 分包商强规则触发器

| 触发条件 | 建议动作 |
|---|---|
| 安全生产许可证失效 | 禁止准入或立即复核 |
| 所属工人存在无证特种作业 | 约谈并限制相关作业 |
| 重大隐患超期未整改 | 分包商风险等级提升至高风险 |
| 同类隐患跨项目重复出现 | 纳入集团级重点关注 |
| 发生责任事故 | 进入事故复盘和履约评价流程 |
| 高风险工人占比持续升高 | 要求分包商开展专项培训 |
| 整改复查多次不通过 | 限制承接新作业面或新项目 |

## 7.5 分包商画像等级

| 风险分 | 等级 | 管理策略 |
|---:|---|---|
| 0-30 | A 级低风险 | 优先合作、常规管理、可作为优秀案例 |
| 31-60 | B 级中风险 | 正常合作、定期检查、风险跟踪 |
| 61-80 | C 级高风险 | 约谈整改、提高检查频次、限制高危作业 |
| 81-100 | D 级极高风险 | 暂停合作、清退出场、纳入黑名单候选 |

## 7.6 分包商画像输出示例

```text
分包商：某劳务工程有限公司
当前风险等级：C级高风险（68分）

主要原因：
1. 近 30 天关联隐患 27 起，其中 5 起整改超期；
2. 所属工人中高风险人员占比 18%；
3. 最近两个月连续出现高处作业 PPE 不合规问题；
4. 复查通过率低于项目平均水平；
5. 当前承担主体结构高处作业，风险暴露较高。

建议动作：
1. 项目部约谈分包商负责人；
2. 要求 7 日内提交专项整改计划；
3. 对其所属高风险工人开展专项补训；
4. 暂不安排新增高处作业面，待复评后恢复。
```

# 8. 三类画像风险传导机制

## 8.1 风险传导逻辑

三类画像不是孤立计算，而应形成风险传导关系。

```text
工人风险
  ↓ 聚合
分包商人员管理风险
  ↓ 传导
项目分包商风险
  ↓ 影响
项目总体风险

项目高危作业状态
  ↓ 放大
工人作业场景风险
  ↓ 反馈
分包商履约风险
```

## 8.2 工人到分包商的传导

工人画像影响分包商画像的“人员管理风险”和“违规行为风险”。

示例指标：

```text
分包商高风险工人占比 = 高风险工人数 / 所属工人总数
分包商培训不合格率 = 培训不合格工人数 / 应培训工人数
分包商严重违规率 = 严重违规次数 / 所属工人出勤人日
```

## 8.3 分包商到项目的传导

分包商画像影响项目画像的“分包商传导风险”。

示例指标：

```text
项目高风险分包商占比 = 高风险分包商数量 / 项目分包商总数
项目分包商整改超期率 = 分包商责任隐患超期数 / 分包商责任隐患总数
项目分包商事故风险 = 分包商事故/险情加权得分
```

## 8.4 项目到工人的反向影响

项目画像影响工人的作业场景风险。例如同一工人在普通项目和高风险项目中的动态风险不同。

```text
工人动态风险 = 个人基础风险 + 当前项目风险修正 + 当前作业场景修正
```

## 8.5 为什么不单独做班组画像

不单独做班组画像的合理性：

1. 班组数据质量通常不如项目、工人、分包商稳定；
2. 班组组织经常变动，画像维护成本高；
3. 分包商是合同和履约管理主体，更适合作为单位画像对象；
4. 工人是行为和健康管理主体，更适合作为个人画像对象；
5. 项目是安全责任和资源调配主体，更适合作为管理画像对象；
6. 班组仍可作为下钻分析维度，不影响责任追踪。

# 9. 四库协同存储架构

## 9.1 总体原则

四库协同遵循“数据按特征分库、业务按主键贯通、画像按统一 ID 聚合”的原则。

| 数据库 | 职责 | 画像相关用途 |
|---|---|---|
| MySQL | 结构化业务事实主库 | 存储项目、工人、分包商、隐患、评分结果、训练样本 |
| Neo4j | 安全关系图谱 | 存储项目-分包商-班组-工人-隐患-事故关系 |
| Milvus | 向量知识库 | 存储规范、案例、整改经验、事故描述、行为记忆向量 |
| Redis | 缓存与状态 | 缓存画像结果、问数结果、会话、预警状态 |

## 9.2 统一 ID 体系

必须建立统一 ID：

| 对象 | ID 示例 | 说明 |
|---|---|---|
| 项目 | project_id | 集团统一项目编码 |
| 分包商 | subcontractor_id | 统一社会信用代码或内部供应商编码 |
| 工人 | worker_id | 劳务实名制人员 ID |
| 班组 | team_id | 仅作为组织关系 ID，不作为独立画像主键 |
| 隐患 | hazard_id | 隐患台账 ID |
| 事故案例 | accident_case_id | 事故/险情案例 ID |
| 画像任务 | profile_task_id | 画像计算任务 ID |

## 9.4 Neo4j 图谱模型

```cypher
(:Project {id, name, type, region, phase})
(:Subcontractor {id, name, qualification, risk_level})
(:Team {id, name})
(:Worker {id, work_type, risk_level})
(:Hazard {id, type, level, status})
(:AccidentCase {id, type, severity})
(:Operation {id, type, risk_level})
(:Rule {id, name, clause})

(:Project)-[:HAS_SUBCONTRACTOR]->(:Subcontractor)
(:Subcontractor)-[:HAS_TEAM]->(:Team)
(:Team)-[:HAS_WORKER]->(:Worker)
(:Worker)-[:BELONGS_TO]->(:Subcontractor)
(:Hazard)-[:LOCATED_IN]->(:Project)
(:Hazard)-[:RESPONSIBLE_PARTY]->(:Subcontractor)
(:Hazard)-[:RELATED_TO_WORKER]->(:Worker)
(:Worker)-[:PARTICIPATES_IN]->(:Operation)
(:Operation)-[:LOCATED_IN]->(:Project)
(:AccidentCase)-[:SIMILAR_TO]->(:Hazard)
(:Hazard)-[:VIOLATES]->(:Rule)
```

注意：`Team` 是关系节点，不建设 `TeamRiskProfile`。

# 10. 多 Agent 体系设计

## 10.1 Agent 总体架构

平台采用“主控 Agent + 专项 Agent + 工具层”的设计。

```text
用户请求
  ↓
主控 Agent Orchestrator
  ↓
意图识别 / 权限校验 / 任务拆解
  ↓
专项 Agent 调度
  ├── 智能问数 Agent
  ├── 画像分析 Agent
  ├── 隐患整改 Agent
  ├── 风险预警 Agent
  ├── 报告生成 Agent
  ├── 场景化出题 Agent
  ├── 分包商评价 Agent
  ├── 安全知识库 Agent
  └── 事故归因 Agent
  ↓
工具调用：SQL / Cypher / Milvus / Redis / 规则引擎 / 贝叶斯模型
  ↓
结果汇总、解释生成、审计留痕
```

## 10.2 画像分析 Agent

画像分析 Agent 是本版本新增核心 Agent，负责三类画像的查询、解释、比较和管理建议生成。

典型问题：

- “当前风险最高的 10 个项目是什么？”
- “A 项目的风险为什么升高？”
- “某工人为什么被判定为高风险？”
- “某分包商近三个月安全表现如何？”
- “哪些分包商在多个项目上重复出现临边防护隐患？”

处理流程：

```text
用户问题
  ↓
识别画像对象：项目 / 工人 / 分包商
  ↓
调用画像结果表和图谱关系
  ↓
必要时检索事故案例和规范依据
  ↓
生成风险解释和管理建议
  ↓
返回自然语言答案与可视化数据
```

## 10.3 智能问数 Agent

智能问数 Agent 用于自然语言查询项目、工人、分包商画像相关指标。

示例：

```text
问题：本月高风险分包商数量最多的项目有哪些？
查询：project_risk_profile + subcontractor_risk_profile
输出：项目排名、分包商数量、主要风险原因。
```

NL2SQL 必须具备：

1. 只读查询；
2. 项目权限过滤；
3. 指标口径映射；
4. SQL 白名单校验；
5. 查询结果解释；
6. 问数审计日志。

## 10.4 风险预警 Agent

风险预警 Agent 基于三类画像结果自动触发预警。

预警规则示例：

| 预警对象 | 触发条件 | 动作 |
|---|---|---|
| 项目 | 项目风险分 ≥ 80 | 推送集团/区域安全负责人 |
| 项目 | 重大隐患超期 | 生成督办任务 |
| 工人 | 工人风险分 ≥ 80 | 通知项目安全员和分包负责人 |
| 工人 | 特种作业证过期 | 限制作业准入 |
| 分包商 | 分包商风险等级 D | 触发约谈和整改计划 |
| 分包商 | 跨项目重复隐患 | 生成分包商专项分析报告 |

## 10.5 场景化出题 Agent

场景化出题 Agent 根据画像结果生成个性化题目。

输入：

- 工人画像；
- 工种；
- 当前作业；
- 近期违规；
- 安全考核错题；
- 事故案例库；
- 项目当前风险。

输出：

- 个性化安全题；
- 班前教育题；
- 专项复训题；

示例：

```text
若工人近期出现“高处作业未系安全带”，系统自动推送：
1. 高处作业安全带使用规范题；
2. 临边洞口防护识别题；
3. 高处坠落事故案例题；

```

## 10.6 报告生成 Agent

# 11. 事故案例库与算法验证机制

## 11.1 建设事故案例库的必要性

你提出“导入事故案例，验证算法合理性”非常关键。画像评分模型不能只靠专家拍脑袋设权重，必须用事故案例、险情案例、近失事件和历史隐患数据进行验证。

事故案例库主要用于：

1. 检验画像评分是否能提前识别高风险对象；
2. 优化各指标权重；
3. 为贝叶斯归因提供先验概率；
4. 为 Agent 生成整改建议和培训题提供案例依据；
5. 为项目复盘和安全教育提供素材。

## 11.2 案例数据来源

| 来源 | 示例 |
|---|---|
| 集团内部事故案例 | 项目事故、险情、近失事件、处罚通报 |
| 项目隐患历史数据 | 重大隐患、重复隐患、整改超期记录 |
| 行业公开案例 | 住建领域典型事故案例、事故调查报告 |
| 视频 AI 事件 | PPE违规、危险区域闯入、违章作业告警 |
| 培训错题数据 | 与事故类型相关的高频错题 |

## 11.3 案例标签体系

每个事故案例应结构化标注：

| 标签类别 | 标签示例 |
|---|---|
| 事故类型 | 高处坠落、物体打击、触电、坍塌、机械伤害、火灾 |
| 作业场景 | 高处作业、临电、吊装、动火、有限空间、深基坑 |
| 直接原因 | PPE不规范、防护缺失、设备故障、违章操作 |
| 间接原因 | 培训不足、交底不到位、监管缺位、赶工期、分包管理弱 |
| 涉及主体 | 项目、分包商、工人、设备、区域 |
| 严重程度 | 一般险情、严重险情、一般事故、较大事故、重大事故 |
| 可预警指标 | 事故前是否有重复隐患、整改超期、违规高发、培训不合格 |

## 11.4 算法验证方法

### 11.4.1 历史回测

用事故发生前 7 天、30 天、90 天的数据计算当时的画像风险分，检查事故主体是否被识别为高风险。

```text
事故案例 T 日发生
  ↓
截取 T-30 日以前的数据
  ↓
计算项目、工人、分包商画像风险分
  ↓
判断是否命中高风险等级
  ↓
统计命中率、误报率、漏报率
```

### 11.4.2 指标贡献分析

分析事故案例中哪些指标贡献最大：

- 违规行为是否更敏感；
- 整改超期是否是强信号；
- 安全考核不合格是否具有预测价值；
- 体检健康状况是否与特定作业风险相关；
- 分包商历史风险是否会传导到项目。

### 11.4.3 权重校准

初期采用专家权重，后期根据案例回测结果进行调整。

```text
专家初始权重
  ↓
事故案例回测
  ↓
统计漏报/误报
  ↓
调整权重和强规则
  ↓
上线灰度验证
  ↓
形成版本化模型
```

## 11.5 模型评估指标

| 指标 | 说明 |
|---|---|
| 高风险命中率 | 事故前被识别为高风险的比例 |
| 漏报率 | 事故前未识别风险的比例 |
| 误报率 | 被判高风险但未发生问题的比例 |
| 预警提前量 | 提前多少天发现风险 |
| Top-K 命中率 | 风险排名前 K 的对象中命中事故主体比例 |
| 管理有效性 | 预警后整改是否降低风险 |

# 12. 贝叶斯归因与风险预测模型

## 12.1 模型定位

贝叶斯模型不替代画像评分，而是作为事故归因和风险预测的概率推理引擎。

画像评分回答：

> 谁风险高？

贝叶斯归因回答：

> 为什么风险高？如果发生事故，最可能的原因是什么？

## 12.2 贝叶斯节点设计

建议按“人、机、料、法、环、管”建立节点。

| 类别 | 节点示例 |
|---|---|
| 人 | 培训不足、违规操作、疲劳作业、健康不适配、无证作业 |
| 机 | 设备故障、维保缺失、防护装置失效 |
| 料 | 易燃材料堆放、材料堆码不稳 |
| 法 | 方案缺失、交底不到位、作业票不规范 |
| 环 | 大风、高温、夜间照明不足、交叉作业 |
| 管 | 监管缺位、整改不闭环、分包管理弱、赶工期 |
| 结果 | 高处坠落、触电、物体打击、坍塌、火灾、机械伤害 |

## 12.3 与三类画像联动

| 画像 | 输入贝叶斯模型的变量 |
|---|---|
| 项目画像 | 高危作业强度、整改超期、重复隐患、环境风险 |
| 工人画像 | 培训不足、违规行为、健康适配、疲劳风险 |
| 分包商画像 | 管理薄弱、人员高风险占比、整改能力差、历史事故 |

## 12.4 输出结果

贝叶斯模型输出：

1. 事故类型概率；
2. 关键风险因素排序；
3. 原因贡献度；
4. 风险传播路径；
5. 管控措施优先级。

示例：

```text
预测结果：A 项目未来 7 天高处坠落风险偏高
主要贡献因素：
1. 临边防护重复隐患：贡献 32%
2. 高风险分包商承担高处作业：贡献 24%
3. 所属工人 PPE 违规频发：贡献 18%
4. 当前存在赶工期和交叉作业：贡献 15%
5. 高处作业专项培训不合格率偏高：贡献 11%
```

# 15. 安全、合规与模型治理

## 15.1 数据权限

| 用户角色 | 可访问范围 |
|---|---|
| 集团管理人员 | 全集团项目和分包商统计，可查看脱敏工人画像 |
| 区域/工程局管理人员 | 所属区域或单位范围内数据 |
| 项目经理 | 本项目数据 |
| 项目安全员 | 本项目工人、隐患、分包商画像 |
| 分包商负责人 | 本单位在本项目的相关数据，不可查看其他单位 |
| 工人本人 | 可查看个人培训、考核、整改建议，不展示敏感评分细节 |

## 15.2 年龄和健康数据合规边界

必须遵循以下原则：

1. 最小必要原则：只采集与作业安全相关的数据；
2. 目的限定原则：仅用于安全适配、准入提醒和风险预防；
3. 脱敏展示原则：健康明细不向无关人员展示；
4. 禁止歧视原则：年龄和健康状况不应作为简单惩罚依据；
5. 人工复核原则：涉及作业限制、岗位调整时必须人工确认；
6. 可申诉原则：工人和分包商应有申诉、复核和数据纠错机制。

## 15.3 模型治理

| 治理项 | 要求 |
|---|---|
| 版本管理 | 每次权重调整形成模型版本 |
| 审计留痕 | 每次评分和预警保留数据快照 |
| 人工复核 | 高风险结论、作业限制、分包商清退建议需人工确认 |
| 偏差检测 | 定期检查是否对年龄、工种、地区产生不合理偏差 |
| 回测验证 | 定期用事故案例库进行模型效果评估 |
| 可解释输出 | 所有高风险画像必须给出原因和建议 |

## 15.4 NL2SQL 安全控制

1. 只允许 SELECT 查询；
2. 自动注入用户权限过滤；
3. 高敏字段脱敏；
4. 禁止查询个人健康明细，除非有授权；
5. 查询结果记录审计日志；
6. 重要统计口径来自指标语义层。

# 16. 实施路线与 MVP 建设计划

## 16.1 MVP 建设目标

## 16.2 分阶段计划

| 阶段 | 周期 | 建设内容 | 交付物 |
|---|---|---|---|
| 第一阶段 | 1-2个月 | 数据梳理、统一ID、指标字典、画像规则初版 | 数据模型、指标体系、原型 |
